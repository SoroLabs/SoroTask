# Offline-First PWA Mode (#1240)

Makes SoroTask installable and usable through a network outage: the app shell
and static assets are served from a service worker cache, the last-known task
list is mirrored into IndexedDB so the dashboard still paints, and anything the
user writes is queued and replayed automatically when connectivity returns.

This supersedes the "primitives only" spike in
[`offline-support.md`](./offline-support.md), which deliberately deferred the
service worker and PWA install. The primitives it shipped
(`useOnlineStatus`, `ActionQueue`, `<OfflineStatusBar>`) are all still in use.

## Architecture

| Piece                   | Path                                                                                    | Role                                                             |
| ----------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| IndexedDB handle        | [`src/lib/offline/db.ts`](../src/lib/offline/db.ts)                                     | One connection helper and one versioned upgrade for every store  |
| Task-config queue       | [`src/lib/offline/taskConfigDb.ts`](../src/lib/offline/taskConfigDb.ts)                 | Drafts awaiting submission, with a per-item `syncState`          |
| Read cache              | [`src/lib/offline/taskStateCache.ts`](../src/lib/offline/taskStateCache.ts)             | Last-known task list, stamped with `cachedAt`                    |
| Reconnect orchestration | [`src/lib/offline/backgroundSync.ts`](../src/lib/offline/backgroundSync.ts)             | Drains the queue, refreshes the cache, registers Background Sync |
| React binding           | [`src/lib/offline/OfflineSyncProvider.tsx`](../src/lib/offline/OfflineSyncProvider.tsx) | Single subscriber, exposed via `useOfflineSync()`                |
| Service worker          | [`public/sw.js`](../public/sw.js)                                                       | App-shell caching + Background Sync bridge                       |
| Manifest                | [`public/manifest.json`](../public/manifest.json)                                       | Installability, shortcuts                                        |
| Icons                   | [`public/icons/`](../public/icons)                                                      | Generated by `scripts/generate-pwa-icons.mjs`                    |
| Registration            | [`app/ClientInit.tsx`](../app/ClientInit.tsx)                                           | Registers the worker and relays its messages                     |

### Why one database

`db.ts` owns the connection and the `onupgradeneeded` transaction so that a
version bump creates or migrates every store atomically. Each operation opens
and closes its own connection, which keeps the module usable from a service
worker, a module-level singleton, and `fake-indexeddb` without any of them
leaking an open handle that blocks the next upgrade.

`OFFLINE_DB_VERSION` is 2; v1 held `task-configs` alone, v2 added
`task-state` and `task-drafts`.

## Read-only offline mode

A failed fetch is not an acceptable answer for the dashboard, so every
successful task read is mirrored into `task-state`. `cacheTasks()` performs a
**full replace** inside one transaction rather than a per-row upsert, because
that is what makes deletions propagate: a task removed on-chain has to
disappear from the offline view too.

Entries carry `cachedAt` so the UI can tell the user how stale the data is
instead of silently presenting a week-old snapshot as current.

## Write queue and replay

`syncTaskConfigs(push)` drains every `pending` config through an injected
`push` callback. Each item is independent — a failure leaves that config
pending and does not abort the batch.

`runSync` tracks the write counts **outside** its `try` block. A later failure
(a dead indexer during the cache refresh) must not erase the fact that the
writes already landed; reporting `synced: 0` there would tell the user their
queued work was lost when it was in fact submitted.

The `push` callback is injected rather than imported so this module owns no
wallet or RPC concern, which is also what makes the whole flow testable
without a chain.

### Background Sync

The service worker cannot replay writes itself — the queue lives in IndexedDB
behind a typed API. So it registers on the `sorotask-offline-sync` tag and, when
the browser fires `sync`, posts a message to every open client. `ClientInit`
turns that into a `sorotask:replay-queue` DOM event, and
`OfflineSyncProvider` performs the drain.

Where Background Sync is unavailable (Safari, Firefox) the `online` event is
the only signal, which means the replay only happens in a live tab.

`online` events are debounced (750 ms by default): browsers fire one per
interface flap, and a flapping connection would otherwise start a burst of
overlapping drains.

## Service worker strategy

| Request kind        | Strategy                                                     |
| ------------------- | ------------------------------------------------------------ |
| Navigations         | Network-first with a 3 s timeout → cached shell → `/offline` |
| `/_next/static/*`   | Cache-first (content-hashed, cannot go stale)                |
| `/api/*` reads      | Network-first, cache fallback, `Response.error()` if neither |
| Other static assets | Stale-while-revalidate                                       |
| Everything else     | Not intercepted                                              |

Only same-origin `GET` is eligible; mutating traffic is never replayed from
cache.

### The pre-cache fix

`CORE_ASSETS` is added **individually**, not with `cache.addAll`. `addAll` is
atomic — one 404 rejects the promise and leaves the worker uninstalled, which
is exactly how the missing `public/icons/` directory used to break the PWA
entirely. A broken entry now degrades to "not cached offline".

## Configuration

| Variable                       | Default | Effect                                               |
| ------------------------------ | ------- | ---------------------------------------------------- |
| `NEXT_PUBLIC_DISABLE_SW`       | unset   | Set to `"true"` to never register the worker         |
| `NEXT_PUBLIC_ENABLE_SW_IN_DEV` | unset   | Set to `"true"` to register the worker in `next dev` |

Registration is no longer gated on `NODE_ENV` alone: the worker only caches
same-origin `GET`s, and gating it meant the offline path could not be exercised
outside a production build. The dev opt-in keeps HMR safe for anyone who does
not want it locally.

## Regenerating icons

```bash
node scripts/generate-pwa-icons.mjs
```

The artwork is defined as pixel data in the script and encoded to PNG on
demand, rather than committing opaque binaries with no provenance. The
manifest and `app/layout.tsx` previously referenced `public/icons/*.png`, which
did not exist — every installability check was failing on 404s.

## Known limitations

- `navigator.onLine` reports `true` behind some captive portals, so the app can
  believe it is online when it is not. Reads degrade to the IndexedDB cache.
- Without Background Sync, queued writes only replay in a live tab.
- The read cache is not encrypted. It holds task metadata, not keys.

## Testing

```bash
npm test -- src/lib/offline
npm test -- src/components/__tests__/OfflineStatusBar
```

`fake-indexeddb/auto` is imported for side effects; each suite deletes the
database in `beforeEach` rather than just clearing it, because a leftover
connection blocks the next version upgrade.
